# 08 · 测试指南

`tests/` 下 7 个文件、**55 个用例**,无任何真实网络依赖(上游 Tavily 与告警 webhook 全部由脚本化的 Fake/mock 顶替),`uv run python -m pytest` 一次跑完约十几秒(含真实起服务的集成测试)。

## 技术选型

| 工具 | 用途 |
|---|---|
| pytest + pytest-asyncio | `asyncio_mode = "auto"`(async 测试函数无需装饰器),fixture 循环作用域为 function |
| respx | mock httpx 传输层,测 `TavilyClient` 的真实 HTTP 行为(头、状态码) |
| fastmcp Client | 以真实 MCP 客户端身份做端到端集成测试 |
| uvicorn + threading | 集成测试里把整个 app 跑在真实端口上 |

配置在 `pyproject.toml` 的 `[tool.pytest.ini_options]`。

## 运行方式

```bash
uv run python -m pytest            # 全量(推荐)
uv run python -m pytest tests/test_pool.py -v    # 单文件
uv run python -m pytest -k failover -v            # 按关键字
```

> **坑:必须用 `python -m pytest`,不能直接 `uv run pytest`。** 本项目 `[tool.uv] package = false`,`app` 包没有安装进环境;`python -m` 会把 CWD 加进 `sys.path`,而 pytest 入口脚本不会。直接 `uv run pytest` 会报 `ModuleNotFoundError: No module named 'app'`。(根 README 里的 `uv run pytest` 在干净环境不可用,以本页为准。)

Windows 下集成测试(真实 uvicorn 线程)同样可跑,`ServerHandle` 用 `port=0` 自动分配空闲端口。

### FakeTavily — 可脚本化的上游替身

继承真实 `TavilyClient`,只覆写 `_request`,不碰网络:

```python
fake.calls                     # 记录每次 (api_key, path),断言"到底调了几次上游"
fake.queue("tvly-test-key-a", TavilyError(429, "…"), …)
                               # 按 key 前缀排队结果:dict=成功响应,TavilyError=抛错
fake.default_response          # 队列耗尽/未命中时的兜底
```

匹配规则:`api_key.startswith(前缀)` 且队列非空 → 弹出队首;非 `/usage` 响应自动补 `request_id`。这套"**按 key 编排剧本**"的机制正是验证故障转移的关键——让 key A 必失败、其余成功,即可断言调度器换了 key。

另有一组现成响应常量:`SEARCH_OK`(含 `usage.credits=1.0`)、`USAGE_OK`(key/account 双层 usage)、`RESEARCH_PENDING`(201 提交响应)与 `RESEARCH_DONE`(完成响应,`usage.credits=5.0`)。

## 文件与覆盖点

### test_pool.py(13 例)— KeyPool 状态机

轮询顺序(1→2→3 循环)、429 冷却与到期懒恢复、exhausted/disabled 被跳过、跨过 plan_limit 自动置 exhausted、`apply_usage` 恢复/保持耗尽、月初滚动清零并复活、添加去重、删除、启停、恢复提示文案、月度时间函数。

### test_tavily.py(7 例)— 上游客户端(respx)

Bearer 头正确发送、嵌套 `detail.error` 错误解析、网络错误映射为 `status=0`、`/usage` GET、`parse_usage` 三种形态(key 级有限额 / key 级无限额回退账户级 / 完全未知结构不炸)。

### test_auth_executor.py(15 例)— 鉴权与执行器

verifier 接受有效/拒绝未知与已吊销 Token、RateLimiter 窗口与按 token 隔离、执行器成功路径(池计数 + request_logs 落库)、429 换 key 成功、432 置耗尽、401 置禁用、**4xx 单次调用即透传不重试**(`len(fake.calls) == 1`)、全池不可用抛 pool_exhausted 且**零上游调用**、重试上限(3 个 key 全 429 → 恰好 3 次调用)、查询词落库(query 列记录 search 的 query)。

research 专属 4 例(`fast_poll` fixture 把轮询间隔压到 10ms、超时压到 0.5s):提交后固定同 key 轮询至 completed(校验 calls 路径 `/research` → `/research/{id}`、credits 与日志记账)、POST 阶段 429 换 key 提交成功、轮询中 401 禁用 key 并中止任务、永远 pending 时按模型超时报错。

### test_integration.py(12 例)— 端到端

核心是 `running_server` 上下文管理器,它**手工复刻 `main.create_app()` 的组装**:

```python
build_mcp(state, lifespan) → mcp.http_app(path="/mcp")
  .routes += /health
  .routes += build_admin_routes(config)
QueryTokenAuthMiddleware(app)            # 与生产同款最外层包裹
→ ServerHandle:uvicorn.Server 跑在守护线程,port=0
```

覆盖场景:

| 用例 | 验证 |
|---|---|
| 未鉴权连接被拒 | 无 Token 时 `list_tools` 直接失败 |
| URL query token | `/mcp?token=…` 无需请求头即可调工具;伪造 Token 仍被拒 |
| 完整链路 | 列出 6 工具 → 432 触发故障转移后成功 → tier 门禁拒绝 crawl → `get_my_usage` |
| research 端到端 | full 等级 Token 走提交+轮询拿回报告与来源;standard 等级被 tier 门禁拦截且**零上游调用** |
| Token 工具白名单 | allowed_tools 只含 search 的 Token:search 成功、extract 被拒(零上游调用)、get_my_usage 仍可用 |
| 全量校准端点 | POST /api/keys/sync-all 用 USAGE_OK 校准全部 key(credits=150 回填进池) |
| RPM 限流 | rpm_limit=2 的 Token 第 3 次调用被拒 |
| Key 测试按钮 | 成功校准额度进池;401 的 key 被禁用 |
| Token 导出 | reveal 拿回明文;legacy 行(无 token_enc)返回友好 reason |
| 设置流 | public-info 默认值、未登录改设置 401、站名/公告、图标上传/读取/重置、改密后新旧密码行为 |
| 日志含 IP | 一次真实调用后 `/api/logs` 记录 `client_ip=127.0.0.1` |
| 管理端鉴权 | 无会话 401 → 登录 → keys/overview 200 |

细节:`usage_first_tavily` fixture 把 `default_response` 设为 `USAGE_OK`——因为后台 usage-sync 任务**启动即跑第一轮**,必须给它一个合法答案,否则首个 key 会在测试中途被标失败。

### test_alerts.py(7 例)— 告警模块(respx / monkeypatch)

key_disabled 告警送达与按 key 去重(不同 key 仍告警)、key_exhausted 默认关闭、全池死→恢复两次状态翻转消息、pool_low_active 阈值(≤比较)、未配置 webhook 时完全静默。邮件渠道 2 例:配置齐全时事件经 `_send_email` 送出(monkeypatch 记录调用,校验主题与配置传递)、配置缺失时事件静默且「测试告警」返回缺失字段提示。

### test_metrics.py(1 例)— Prometheus 导出

log_request 落日志后计数器递增;`/metrics` 响应含全部指标族(gauge 从池快照实时计算;计数器为进程级累计,断言只做存在性与下限检查)。

## 编写新测试的建议

- 优先用 `FakeTavily.queue()` 编排剧本,而不是 mock KeyPool——让状态机真实流转
- 断言"副作用三件套":内存态(`ks.effective_status`)、持久化(`db.fetchone`)、日志(`request_logs`)
- 涉及新路由/中间件时,把用例放进 `test_integration.py` 的 `running_server`,与生产组装方式保持一致
- async 用例直接写 `async def test_…`,无需标记(auto 模式)
