# 09 · 部署与运维

## 环境变量(全部经 `app/config.py` 读取)

| 变量 | 默认 | 说明 |
|---|---|---|
| `ADMIN_PASSWORD` | **必填** | 管理密码。缺省且非 dev 模式直接拒启;一旦在控制台改过密码,以库内哈希为准(见 [05](05-管理API.md)) |
| `TAVILY_POOL_DEV` | 未设 | `=1` 开启 dev 模式:密码默认 `admin`、日志 DEBUG、`COOKIE_SECURE=0` |
| `DATA_DIR` | `./data` | SQLite / session_secret / site_icon.bin 所在目录;**容器内固定 `/data`** |
| `SESSION_SECRET` | 自动生成 | 缺省时生成并持久化到 `DATA_DIR/session_secret`;变更 = 所有会话失效 + Token 无法导出 |
| `HOST` / `PORT` | `0.0.0.0` / `8000` | 监听地址 |
| `KEYPOOL_COOLDOWN_SECONDS` | `60` | 429 后 key 冷却秒数 |
| `KEYPOOL_MAX_RETRIES` | `4` | 单次调用最大换 key 次数(实际取 `min(池大小, 该值)`) |
| `USAGE_SYNC_INTERVAL_HOURS` | `6` | 配额校准周期(启动立即跑一轮;下限 60s) |
| `LOG_RETENTION_DAYS` | `30` | 请求日志保留天数 |
| `DEFAULT_TOKEN_RPM` | `30` | 新建 Token 的默认 RPM |
| `CHARACTER_LIMIT` | `25000` | 工具输出截断字符数 |
| `COOKIE_SECURE` | dev `0` / 生产 `1` | 会话 Cookie 的 Secure 位;纯 http 本地调试才设 0 |

## 本地开发

```bash
# 后端
uv sync
TAVILY_POOL_DEV=1 uv run uvicorn app.main:app --port 8000

# 前端(另开终端,Vite 5173 代理 /api /mcp → 8000)
cd dashboard && npm install && npm run dev

# 测试(注意必须 python -m,见 08 篇)
uv run python -m pytest
```

## Docker 镜像(Dockerfile)

两阶段构建:

```
Stage 1  node:22-slim      → npm ci && npm run build        → /build/dist(前端产物)
Stage 2  python:3.12-slim  → uv sync --frozen --no-dev     → /srv/.venv(锁定的依赖)
                           → COPY app/ + 前端 dist
                           → 非 root 用户 appuser,/data 卷挂载点
```

要点:

- **依赖先拷**(`pyproject.toml` + `uv.lock`),锁文件不变就命中缓存层
- `uv sync --frozen --no-dev --no-install-project`:只装三方依赖(本项目非安装包),`UV_COMPILE_BYTECODE=1` 预编译字节码
- 非 root 运行;`HEALTHCHECK` 每 30s 探测 `/health`
- 启动命令 `python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`

## Compose 拓扑(两份)

| | 根目录 `docker-compose.yml` | `deploy/docker-compose.yml` |
|---|---|---|
| 镜像 | `build: .`(本地构建) | `ccr.ccs.tencentyun.com/yjkz/tavily-map:latest`(腾讯云 TCR) |
| 容器名 | 自动 | `tavily-map` |
| 端口绑定 | `10.0.0.8:${APP_PORT:-8000}`(作者内网 IP,局域网可见) | `127.0.0.1:${APP_PORT:-8000}`(**仅回环**,公网只走 Nginx) |
| 数据 | 命名卷 `app-data` → `/data` | 同左 |
| env | `env_file: .env` | 同左 |

> 根目录这份绑的是作者自己的内网地址(10.0.0.8),换环境部署时改成 `127.0.0.1` 或按需调整;对外服务一律走 Nginx 反代 + TLS。

## CI/CD(`.github/workflows/deploy.yml`)

push 到 `main` 触发,两个 job 均绑定 GitHub Environment `腾讯云4h4g`;`concurrency: tavily-map-production`(不取消进行中的部署,排队串行):

```
job1 build   → docker build 打双标签 :${{ github.sha }} 与 :latest
             → push 到 TCR(ccr.ccs.tencentyun.com/yjkz/tavily-map)
job2 deploy  → scp deploy/docker-compose.yml → 服务器 /home/deploy/tavily-map/
             → ssh: docker login + compose pull + compose up -d
```

所需 secrets:`DOCKER_PASSWORD`(TCR 密码)、`SERVER_HOST`、`SERVER_USER`、`SERVER_SSH_KEY`。

回滚:服务器上 `docker tag`/改 compose 的 tag 为历史 `:sha` 再 `up -d` 即可(镜像按 commit sha 保留)。

## Nginx 反向代理(宿主机)

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;          # MCP Streamable HTTP 流式响应必须关缓冲
    proxy_read_timeout 3600s;     # 长连接(crawl 可能几分钟)
}
```

`X-Forwarded-For` 是 `get_client_ip()` 的数据来源(取首跳),Nginx 是唯一可信入口。WebSocket 无关(本项目只用 Streamable HTTP)。

## 数据与备份

卷 `app-data`(`/data`)里三样东西(详见 [06](06-数据模型.md)):

| 文件 | 丢失后果 |
|---|---|
| `tavily_pool.db` | 全部 key/Token/日志/设置丢失——**定期备份**(`sqlite3 .backup` 或直接停容器拷文件,WAL 模式下热拷 db 文件不完整) |
| `session_secret` | 所有会话失效、Token 导出功能报废(明文不可恢复,只能全部重建 Token) |

## 运维要点

### 日志

- 容器 stdout(uvicorn + 应用 logger `tavily_pool`):每轮 usage-sync / maintenance 结果、key 测试、改密等关键事件
- `docker logs tavily-map -f --tail 100` 即可覆盖绝大多数排障

### 性能特征(容量规划)

- **单进程全异步**(uvicorn + httpx + aiosqlite),1C1G 的 VPS 即可承载小团队
- SQLite 单连接:aiosqlite 在后台线程**串行**执行语句,写吞吐有限但本项目写入量极小(每请求 1-2 条日志 + 限额聚合读)
- 日/月配额检查是 `request_logs` 实时聚合,靠 `(token_id, ts)` 索引;日志 30 天滚动清理控制表规模,长期不退化
- RPM 限流器与登录防爆破均为进程内存态,**重启清零**(有意的轻量设计)
- 告警走内存队列 + 后台发送任务,webhook 故障不影响请求路径

### 监控(/metrics)

`/metrics` 暴露 Prometheus 文本格式(公开,但只有聚合数值,无 key/查询明文):

- `tpm_requests_total{tool,status}`、`tpm_credits_total` — 计数器,随日志写入递增
- `tpm_pool_keys{status}`、`tpm_pool_remaining_credits`、`tpm_tokens_active` — gauge,抓取时实时计算
- 附带 prometheus-client 默认的 python 进程指标

不希望公网可见时在 Nginx 层拦截 `location /metrics` 即可。

### 常见故障排查

| 症状 | 排查 |
|---|---|
| 客户端 401 | Token 被吊销/删除;`?token=` 是否被中间设备剥掉;改用 Bearer 头验证 |
| 全部请求报 "All Tavily keys are unavailable" | 控制台看池状态:429 冷却等 60s;432/433 等月初或点「测试连接」校准;401 需换 key |
| 登录后仍被踢回登录页 | `COOKIE_SECURE=1` 但走了 http → Nginx 挂 TLS 或临时设 0 |
| Token 导出报"SESSION_SECRET 已变更" | 换过 secret 的历史遗留,删 Token 重建 |
| 邮件告警发送失败 | 163/QQ 等邮箱密码栏应填**授权码**(非登录密码);端口/SSL 组合(465+SSL / 587+关);先用「发送测试告警」按钮验证 |
| MCP 连接频繁断开 | Nginx `proxy_buffering` 是否为 off、`proxy_read_timeout` 是否够长 |
| 改了 `.env` 密码不生效 | 已在控制台改过密码,库内哈希优先;用新密码登录或重置库 |

### 安全清单

- [x] 公网仅暴露 Nginx 443;容器只绑回环
- [x] 强 `ADMIN_PASSWORD`;登录 5 次失败锁 10 分钟
- [x] TLS 由 Nginx 终止;会话 Cookie HttpOnly + SameSite=lax + Secure
- [x] 访问 Token 仅存哈希;泄露即控制台吊销(即时生效)
- [x] RPM / 日配额 / 月 Credits 三层限额兜底防滥用
- [x] Tavily key 永不下发给 MCP 客户端
- [ ] Tavily key 在服务器上**明文存储**(转发上游所必需)——依赖服务器与 `data/` 目录权限,不入库不进仓库
- [ ] `?token=` 形式会把凭证留在 URL(与 Tavily 官方 MCP 同款权衡):客户端本地配置文件注意权限,泄露可吊销
